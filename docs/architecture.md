# Module architecture

`index.html` loads one entry point: `src/game.js`. The browser resolves dependencies through explicit imports. There is no bundler or required package installation.

## Ownership

- Data definitions live in `src/world/world.js`, `src/data/items.js`, `src/data/enemy-types.js`, `src/data/action-definitions.js`, and `src/quests/quests.js`. Permanent IDs remain five-digit strings.
- `src/core/state.js` owns mutable player, inventory, enemy, quest, and combat data. Its `runtime` object owns session state, camera coordinates, selected targets, and active shop/charge references. Imported scalar bindings are never reassigned by another module.
- Gameplay modules own state transitions and rules: `src/player/player.js`, `src/player/inventory.js`, `src/player/equipment.js`, `src/player/stats.js`, `src/combat/enemies.js`, `src/combat/spells.js`, `src/quests/quest-system.js`, `src/shops/shops.js`, `src/world/movement.js`, and `src/world/collision.js`.
- UI and render modules read those models and call explicit actions. Rendering does not advance simulation time. Input bindings are registered in `src/core/input.js`; panels own their click/drag handlers.
- `src/game.js` initializes event subscriptions and input once, then calls `update(dt)` and `render()` through `requestAnimationFrame`.

Keep imports acyclic. Gameplay must not import a panel merely to refresh it: announce a change through `src/core/events.js` instead. New session data should have one owner rather than a second copy in a renderer or panel.

## Events

Subscriptions are installed during startup, never on each restart. Notifications are synchronous, so a completed action updates its dependent UI immediately.

| Event | Meaning / consumers |
| --- | --- |
| `player:changed` | Equipment, attributes, XP, or gold changed; refresh the character sheet, XP bar, and ability details |
| `resources:changed` | Health/mana changed outside the regular update; refresh the resource HUD and visible sheet |
| `player:hurt` | Combat pushes active cast progress back by one sixth of its total duration per hit, clamped at zero |
| `enemy:hurt` | Actual health lost, target, and damage source feed visual feedback |
| `combat:notice` | Show a brief interruption or failure notice without altering combat |
| `combat:reset` | Clear transient damage text, hit flashes, notices, and visual timing |
| `player:died` | Lifecycle enters the dead state |
| `game:statechanged` | Start/death screens respond to session transitions |
| `portraits:ready` | Player sprite image finished loading; refresh portraits |
| `quests:changed` | Refresh quest progress and status |
| `shop:requested` | A nearby building interaction requests its shop |
| `shop:opened`, `shop:closed` | Update the modal, focus, and background interaction |
| `shop:changed` | Refresh stock, affordability, inventory capacity, and gold |
| `menu:changed` | Pause modal visibility, keyboard focus, background interaction, and save availability |
| `enemy:defeated` | Roll loot once and create an independent corpse |
| `loot:changed` | Clear stale corpse hover details after drops, pickup, and loading |

Resource bars also update during active simulation. Live character-sheet updates only change displayed resources and preserve inventory controls. Opening the shop pauses simulation using `isPlaying()`; closing it clears held keys and frame timing.

`src/core/pause-menu.js` owns pause transitions through `runtime.menuOpen`. `isPlaying()` gates simulation and gameplay actions while the menu is open, preserving casts and transient effects. Menu transitions clear held input and frame timing. `src/ui/pause-menu-ui.js` owns the dialog, focus trap, and restart controls; save controls remain in `save-ui.js`. Loading or changing session state closes the menu. Escape closes nested Load choices, then the pause menu; outside the menu it closes the shop or topmost gameplay panel before opening pause. Panel closing and focus cleanup live in src/ui/panels.js; input consumes Escape once and ignores repeats.

## Monster loot

Monster levels live on enemy types and can be overridden per world spawn. `src/combat/enemy-stats.js` scales attack damage without changing base damage, HP, or XP. The guarded death handler emits `enemy:defeated`; `setupLoot()` subscribes once at startup, keeping loot separate from combat and avoiding circular inventory/combat imports. `src/data/loot-tables.js` defines gold rules, item chance, and rarity weights. Rarity is rolled before selecting an item within that tier, so adding Common definitions does not dilute Legendary rarity odds.

Shared state owns `corpses` and a monotonic ID counter. Corpses copy the enemy's identity, level, position, and visual fields, then keep one rolled gold amount and optional item ID. They do not reference respawning enemy instances, collide with actors, or expire. Pickup validates active play, membership, range, and solid scenery; gold/items are removed individually, and an empty corpse is deleted. Full inventory retains the item. Rendering reuses flattened slime sprites and a downed wolf fallback; hover uses the shared instant tooltip. E prioritizes an overlapping corpse over a nearby shop.

Version 3 saves whitelist remaining corpse rewards and positions. Validation checks unique IDs, known definitions, level/gold bounds, and coordinates before loading, then visuals are rebuilt from enemy definitions. Versions 1/2 migrate to an empty corpse list; loading never rolls loot. Reset clears session corpses before loading restores saved ones. Save parsing and file import share a size limit.

## Verification

Combat feedback uses transient `state.combatFeedback` arrays, managed by `src/combat/feedback.js` through damage/failure events and delta time. Damage numbers distinguish direct hits, DOT, and incoming damage. Effects are bounded globally and by target lanes; excess same-kind burst hits combine displayed totals. Hit flashes and notices expire independently. `src/rendering/combat-feedback.js` draws them without advancing time, and stun visuals read `enemy.stunRemaining`. Damage fields report actual health lost, excluding overkill. Feedback is excluded from saves and cleared on death and combat reset.

The action bar caches effective ability definitions when assignments/equipment change. `updateActionBarStatus()` reads live cooldowns and `getActionUnavailableReason()` each frame, including while paused, and changes DOM only when countdown text or status changes. Target checks are shared with attack validation. `aria-disabled` communicates unavailability while preserving drag operations and tooltips; combat functions still enforce requirements. `tests/combat-feedback-checks.js` verifies overlapping effects, expiry, pause, statuses, cooldown recovery, stuns, and lifecycle cleanup.

Offensive attribute scaling is centralized in `getSpellStats()` using `STAT_RULES.damagePerAttribute` (1.1 per effective attribute point above 10). Ability weapon categories select Strength, Intelligence, or Dexterity; gear attributes are included once. Direct hits add matching weapon damage, DOT ticks add only their attribute bonus, and results round to tenths. Projectile/effect damage is captured when launched or applied; later gear changes do not rewrite damage already in flight. The existing `fireballs` collection now also holds ranged projectiles tagged with ability ID `00005` and a weapon class for arrow/dagger rendering. Shared projectile updates handle movement, scenery, range, death credit, and cleanup. Ranged Attack reads its equipped weapon's range. New Hunter adventures assign it to slot 5; loading preserves saved action-bar assignments. `tests/attribute-damage-checks.js` covers formulas, restrictions, projectiles, purchases, tooltips, and persistence.

Equipment rarity definitions live in `src/data/rarities.js`; each item declares a rarity key and `itemLevel` in `items.js`. Item level is metadata only. Fixed item stats remain the source of combat bonuses; rarity colors never apply hidden multipliers. `src/ui/item-appearance.js` applies shared colors to inventory, equipment, and shop controls, and item tooltips show both rarity text and level. Sword abilities use shared `meetsWeaponRequirement()` checks with weapon category/class, so upgrading to another sword preserves ability access. Saves keep stable item IDs and resolve rarity/level from definitions without storing duplicate rarity/level metadata. `tests/rarity-checks.js` covers every tier through purchases, equipment, combat, tooltips, and save/load.

Enemy navigation is owned by `src/world/navigation.js`. A* uses a half-tile grid and the existing collision checks with the requesting enemy's dimensions; diagonal edges and bridge transitions validate intermediate movement positions. Search storage is reused, searches have a fixed visit budget, and routes are retained between timed updates. Direct paths avoid A* when unobstructed. Each enemy owns transient route state, cleared on death/respawn and replaced when AI modes change; it is not saved. Unreachable chasing/returning goals retry after a delay; wandering abandons unreachable goals and chooses another after its normal pause. Solid geometry blocks melee attacks as well as navigation.

Persistence lives in `src/persistence/saves.js`, with controls in `src/ui/save-ui.js`. Version 6 snapshots whitelist persistent fields and stable IDs; validation completes before loading mutates shared objects. Loading reuses `resetAdventure()` to clear transient state, restores progress in place, recalculates derived stats, and emits normal UI events. Saves restore the active area at its defined safe spawn. No save/load listeners are registered during loading. `localStorage` holds a current snapshot and previous valid backup; export/import works independently of browser storage. Version 1 snapshots migrate legacy item IDs in inventory/equipment before validation; ability IDs and quest counters are unchanged. Versions 1 through 6 are supported. Migration applies to browser saves, recovery backups, and file imports; version 2 adds an empty corpse list during migration, version 3 adds village area IDs to the player and corpses, version 4 adds the boss quest, and new writes use version 6. Versions 1 through 5 require a class choice before loading; migration moves incompatible equipment into the backpack or rejects the load if space is insufficient. `tests/save-checks.js` checks validation, storage recovery, round trips, quest rewards, and actual controls without leaving test saves behind.

Run `serve.ps1` and open `/tests/smoke.html`. The checks import public module APIs and operate inside an isolated iframe. They do not add debug globals or change the normal game entry point. A restart resets adventure data without registering duplicate handlers.

Area definitions live in src/world/world.js and cave-world.js. areas.js switches the active definition, rebuilds scenery and collision, clears transient attacks, and caches enemy instances while their area is inactive. Corpses carry area IDs and only render or accept interaction in the active area. Portals use safe destination positions and support nearby clicks or E. Cave floor polygons constrain movement; pools, rocks, and walls block traversal while bridges remain open. tests/area-checks.js verifies travel, chamber connectivity, collision, area loot, and save migration.

Boss encounters use enemy type 00004 and src/combat/boss.js. Mutable attack phase, windup, charge direction, cooldown, and animation time live on the enemy instance. The safe entrance corridor controls engagement and retreat; area changes and player death reset unfinished fights. boss-renderer.js draws world-space warnings and a screen-space health bar; boss-sprites.js crops the labelled boss1.png sheet once and renders animation frames without advancing time. Generic damage/death handling still owns XP and quest events; the existing corpse system uses guaranteedLoot for the boss. The completed stonehorn quest is the persistent source of truth for victory, so re-entry/loading suppresses the boss without replaying rewards. Version 5 saves migrate older quest data; active fights load reset at the safe entrance, while completed quests and unlooted corpses persist. tests/boss-checks.js covers attacks, resets, reward idempotence, inventory limits, and save migration.

Quest browsing and tracking are owned by src/ui/quest-ui.js. runtime.selectedQuestId is the single selected quest used by both the journal details and compact side tracker; objective/status data remains in questProgress. L or the tracker button opens a dialog with independently scrolling quest-list and detail panes, fixed header/footer, and keyboard focus handling. Rendering runs on quest events or user actions, not per frame. The journal closes before lower panels on Escape and on death/area changes; selection survives area travel. Saves optionally whitelist selectedQuestId within the versioned schema, so older snapshots remain compatible. A fresh adventure selects the introductory quest. tests/quest-ui-checks.js verifies controls, rewards remaining untouched by selection, saved selection, focus, live progress, and viewport layouts.

Casting abilities default to BASE_CAST_TIME (1.5 seconds) through getSpellStats. Combat owns the active spell ID, elapsed time, duration, target, interruption, and completion effects. Mana and cooldowns start only on completion. src/ui/cast-bar.js reads this state for the HUD, with cached text/progress updates and placement above the measured action bar. Character casting frames follow normalized cast progress.

The player HUD level is refreshed with character resources. src/ui/target-frame.js reads runtime.selectedEnemy each frame and caches unchanged DOM values and idle portraits. Sprite renderers accept an optional drawing context so target portraits reuse the existing slime, wolf, and boss art without changing world rendering. The target frame hides for cleared or dead targets and inactive sessions.

Class definitions live in src/data/classes.js: permanent id, name, mainStat, startingWeapon, startingItems, allowed ability IDs, and optional initial actionBar positions. The player stores only classId; starting selection is separate runtime state. Adding a definition reuses start-screen choices, equipment eligibility, ability filtering, initial quests, and persistence without class-name branches. Items explicitly declare gearCategory; secondary stat bonuses never determine eligibility. Add item families and class definitions together, keeping permanent IDs. There are 85 equipment definitions, including three main-stat families for head/chest/legs/boots and Strength shields; other classes currently have no offhand item. Attribute baselines and damage formulas are unchanged.

Version 6 validates class IDs, equipment categories, and action-bar ownership before applying data. Versions 1-5 first become a validated pending version-5 snapshot; save-ui.js requires a class choice and keeps the current session inert/paused during the dialog. Choosing a class moves incompatible equipment to the backpack, clamps health if Strength bonuses were removed, and filters incompatible action assignments. Insufficient space blocks migration without discarding items or overwriting storage. Escape/Cancel restores the current session and focus. readSave preserves pending migration through backup/file flows.

Run /tests/classes.html for production class restrictions, starting quests, all equipment/class combinations, version-6 validation, migration/cancellation/full-backpack behavior, extension by a new definition, and short/narrow start-screen layout. The existing /tests/smoke.html scenarios use tests/adventurer-fixture.js, a test-only class that permits mixed gear/actions for original combat regressions; it is never loaded by the game or class-specific suite.

Specialization nodes live in src/data/specializations.js, keyed by class ID with permanent ability IDs, prerequisites and normalized node positions. player.specializationPoints plus unlockedSkills.length always equals level minus one. gainXP awards one point per gained level, while player/specializations.js validates and spends points once and fills the leftmost empty slot without replacing action assignments. classes.canUseAbility accepts unlockedSkills explicitly; combat, spell-book filtering, drag/drop, action assignment, and save validation all use it. Class abilities are the level-1 defaults. Other classes retain earned points until trees are defined.

The N dialog is owned by ui/specialization-ui.js, above quest log and other gameplay panels. Headers, close controls and footers remain fixed while nodes scroll. Escape closes it before pause; death, travel, shop and pause transitions close it. Unlock renders follow player events rather than the game loop. Choices are permanent until a fresh adventure.

Version 7 saves whitelist specializationPoints and unlockedSkills and validate unique known nodes, prerequisite closure, point totals, and action ownership before loading. Version 6 migrates without another class choice: all earned points are unspent and assignments for tree skills are cleared. Versions 1-5 retain the existing class-choice migration. Temporary Rend effects and Shield Wall duration are never saved. Rend uses a bounded per-target effect refreshed without delaying the next tick; Cleave checks range, cone and scenery per enemy; Shield Wall reduces post-armor damage for five gameplay seconds with a minimum of one and ends on shield removal. Combat reset/death/travel/loading clear transient effects. Run tests/specializations.html for focused verification.

Specialization layout uses normalized node positions in data/specializations.js. ui/specialization-ui.js draws prerequisite edges with an SVG layer and overlays icon-only buttons. Shared immediate tooltips include current derived damage, effects, costs and prerequisites; aria-disabled nodes stay focusable for keyboard inspection, with actual unlock enforcement in the gameplay helper. Charge is the sole Warrior root, splitting to Shield Wall and Cleave, then Rend beneath Cleave. Version 8 validates this prerequisite closure; valid version-7 Cleave-first builds refund Cleave/Rend and remove only their action assignments. Already-connected builds retain their learned skills.

Learning now always uses actionBarSpells.indexOf(null); specialization nodes no longer carry preferred action slots. The nine Warrior unlocks plus starting Sword Strike fill all ten slots. Shield Bash, Last Stand and War Cry descend from Shield Wall; Whirlwind descends from Cleave; Execute descends from Rend. Shared combat validation handles shield requirements, self-targeted abilities and Execute's strict sub-25% threshold. Shield Bash cancels only explicitly interruptible bossAction windups and briefly stuns ordinary enemies; Stonehorn windups explicitly set interruptible:false. Whirlwind applies one swept-area hit per enemy with scenery checks and a moving spin visual.

War Cry and Last Stand are transient player state. getPlayerStats accepts includeTemporary:false to compute permanent save limits; the Strength shout affects ordinary derived Strength damage and maximum health without healing. Last Stand records a 30% maximum-health snapshot, raises current health, and removes the same health on expiry with a nonlethal minimum. Buff expiry, shield removal, combat reset and death clear transient effects; save snapshots normalize health without modifying the live player, and loading never persists buff benefits. tests/warrior-skill-checks.js runs from specializations.html and covers all ten skills, leftmost assignment, protected/interruptible windups, AoE geometry and scenery, Execute eligibility, pauses, cooldowns, temporary health, death, and save/load.
